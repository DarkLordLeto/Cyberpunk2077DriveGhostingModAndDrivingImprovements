# Owner and driver probe (0.10.0)

Runtime owner resolution and positive driver detection passed on 2026-10-30; passenger/negative driver cases remain untested. All collision callback arguments, outputs and the original return pointer remain unchanged.

The exact-build-guarded helper at RVA 0x314a70 copies a weak owner reference from a generation-checked physics proxy while holding a temporary shared proxy reference. The resolver at 0x27d430 checks the proxy index, generation and active state. The copied control block increments its weak count at +4. Disassembly and callers are preserved in artifacts/native-research/proxy-owner-getter.json.

Only the game Running callback resolves owners and locks their weak handles. No entity pointers are retained. Slots 0 and 1 are inspected independently; their actual classes must be confirmed in-game. Entity IDs require an entEntity RTTI size match. Vehicle queries require the expected no-argument Bool signature. Unknown results are logged as -1.

DNC_DRIVER reports IsPlayerDriver for the mounted vehicle. DNC_PAIR_OWNER reports class, entity, IsPlayerVehicle and HasTrafficSlot for sampled counterparts. These are observations, not a proven NPC classification or an active driver gate. A traffic slot alone does not prove NPC occupancy.

The physics callback only stores bounded scalar samples. Each of the first eight mounted intervals has a separate 64-record budget. Owner resolution is capped at 256 distinct proxy IDs per session; unresolved owners are not retried. A despawn before draining may therefore produce resolved=0. Pair IDs previously all read zero and are not used as unique identities.

Validation: drive a car and motorcycle near moving traffic in one session, then exit. Confirm owner reader ready, driver status, vehicle/world counterpart classes, and clean unload. Neither ghosting nor opacity changes are enabled.

## Implementation consequences

The next runtime integration must publish refreshed, generation-aware vehicle observations from the game thread to the physics callback. Vehicle classification must remain distinct from current traffic membership. Expired, missing, detached, or driver-unknown observations must not initiate suppression. The current two-second mounted-vehicle poll is diagnostic and is not a sufficient driver authorization gate for gameplay.

Do not base first-contact behavior on the delayed sample drain: that runs after the original callback and can miss the first contact. Discover/refresh nearby traffic before pair evaluation, or verify a supported synchronous classification path. Do not call script functions on physics worker threads.

Turning ghosting off during overlap needs explicit pair lifecycle/refilter behavior; a missing registry record alone cannot restore a pair already suppressed by PhysX. Pair IDs were zero in earlier observations and cannot serve as overlap keys. Rendering opacity and restoration remain a separate unresolved integration.

No additional identical driving test is needed for this probe. Keep installed 0.10.0 unchanged while implementing the next integration step.
